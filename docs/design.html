MacroPad Mixer

A volume mixer you can put your hand on. Every key becomes an app that is playing sound, and the knob turns that app up or down without touching the rest of your system audio. Works on macOS and Windows.

Architecture

Two programs and a USB cable

The MacroPad only handles buttons, lights and the screen. A small Python daemon on the computer does the audio work, with one backend per operating system. They talk over a second USB serial port that CircuitPython enables in boot.py, so the normal console stays free for debugging.

Protocol v1

One JSON object per line

The knob sends raw clicks; the computer turns them into volume and answers with the real value, so the computer is always the single source of truth.

DirectionMessageMeaning
Computer → pad{"t":"apps","apps":[…]}Full app list: id, name, vol, mute; newest first
Computer → pad{"t":"vol","id":…,"vol":55,"mute":false}Current state of one app
Computer → pad{"t":"ping"}Heartbeat every 2 s; 6 s of silence means the computer is gone
Pad → computer{"t":"hello","fw":"0.1.0"}Sent on boot and reconnect
Pad → computer{"t":"delta","id":…,"d":-2}Knob clicks for the selected app, batched every 50 ms
Pad → computer{"t":"mute","id":…}Knob pressed: toggle mute
Platforms

Per-app volume on each OS

straightforward

Windows

  • pycaw wraps the same audio-session API the Windows Volume Mixer uses.
  • Group sessions by exe name: Chrome and Discord open several.
  • Scan every active output device, not only the default one.
  • Friendly names come from the exe's file description.
the hard part

macOS

  • No public per-app volume API. Apps that do it use Core Audio process taps (macOS 14.2+).
  • v1 drives FineTune (free, open source, macOS 15+) through its finetune:// URL scheme.
  • FineTune can't report volumes back, so the daemon remembers them.
  • Later: our own Swift helper app using taps directly.
straightforward

Linux

  • pulsectl sets per-stream volume on PulseAudio and PipeWire.
  • Streams are grouped by application name.
  • Untested so far.
